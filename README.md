# UX Audit

中文 UX / 交互合理性审查 Codex Skill，内置可在浏览器打开的本地操作界面。

从 Figma 或其他设计工具复制截图，粘贴或上传后，即可对照原界面查看 UX 审查结果、Top 5 问题、9 层评分、修改规则和页面文案建议。

## 核心能力

- 识别页面目标、目标用户、核心任务和主行动
- 还原用户完成任务的路径
- 用大白话说明最重要的 5 个 UX / 交互问题
- 按 9 大 UX 层面评分
- 给出“改什么、为什么改、改后有什么收益”的修改规则
- 输出基于被审查页面真实文案的替换建议
- 按需生成修改后页面建议图和前后对比看板
- 在浏览器中左右并排查看审查页面与结果

## 使用方式

### 直接在对话中审查

上传界面截图后输入：

```text
使用 $ux-audit 审查这张界面截图，指出体验问题并给出修改建议。
```

需要完整报告时输入：

```text
使用 $ux-audit 做完整审查，并展开 9 大 UX 层面、完整自检和参考来源。
```

需要修改后建议图时输入：

```text
使用 $ux-audit 审查这张图，并生成修改后页面建议图。
```

### 打开 Web 界面

安装 Skill 后，对 Agent 说：

```text
启动 ux-audit
```

或：

```text
打开 UX 审查界面
```

Agent 会从 Skill 自带的 `ui/` 目录启动本地服务，并在浏览器打开实际地址。普通 UX 审查不会自动启动页面，只有明确要求“启动”或“打开界面”时才会打开。

首次启动需要联网安装前端依赖，后续启动不再重复安装。页面仅在本机运行，不会主动发布到公网。

> 当前 Web 界面是本地交互原型，报告内容为示例展示；真实 UX 审查由 Codex 按 `SKILL.md` 和审查规则执行。

## 安装

需要 Node.js `22.13.0` 或更高版本。

将仓库安装到 Codex Skills 目录：

```bash
mkdir -p ~/.codex/skills
git clone https://github.com/SemineChen/ux-interaction-audit.git ~/.codex/skills/ux-audit
```

已经安装过时，更新仓库：

```bash
cd ~/.codex/skills/ux-audit
git pull
```

也可以手动启动 Web 界面：

```bash
cd ~/.codex/skills/ux-audit/ui
npm ci
npm run dev
```

终端会显示实际访问地址；端口被占用时可能不是 `3000`。

## 审查结果

默认输出重点版报告：

1. 页面目标、用户和主行动
2. 当前任务路径
3. Top 5 UX / 交互问题
4. 9 大 UX 层面评分
5. 修改规则清单
6. 文案替换建议
7. 一句话总结

9 大 UX 层面包括：视觉、信息、交互、流程导航、反馈状态、表单与错误、无障碍、信任与风险、情绪体验。

默认只输出文字报告和标注点清单。只有明确提出“生成对比图”“修改后示意图”或“给我图”时，才进入图片产物流程。

## 文件结构

```text
ux-interaction-audit/
├── SKILL.md
├── agents/
│   └── openai.yaml
├── references/
│   └── ux-audit-framework.md
└── ui/
    ├── app/
    ├── public/
    ├── tests/
    ├── package.json
    └── package-lock.json
```

`SKILL.md` 保存调用和执行规则，`references/` 保存完整 UX 审查框架，`ui/` 保存可在浏览器运行的操作界面。

## 适用场景

- App 与 Web 页面体验评估
- Figma 设计稿走查
- 表单、注册、报名和提交流程审查
- 支付、授权、隐私等高风险流程诊断
- 页面层级、交互状态和文案优化
- 修改后页面建议图与前后对比看板

## 设计原则

这个 Skill 不只判断页面“好不好看”，更关注用户能否快速看懂页面、找到下一步、完成任务，并理解操作结果。

修改建议默认保留原页面的业务目标和视觉体系，只优化信息层级、任务路径、交互状态、反馈和文案。
